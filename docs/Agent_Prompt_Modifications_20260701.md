# Agent Prompt 修改记录

## 共享风格指南 video_style_guide

**修改前：**

各个 Agent 没有统一的视频风格判断标准。即使用户明确指定“抖音短视频”“电影”“脱口秀”等类型，流程仍容易按完整影视叙事去补人物铺垫、冲突闭环和圆满结局，导致不同题材最后都偏向“善恶有报、大团圆、所有人和解”的收束方式。

**修改后：**

新增 `backend/src/prompt_files/video_style_guide.py`，统一定义四类视频风格，并作为 `{video_style_guide}` 注入到相关 Agent prompt 中：

- 抖音短视频：极速节奏、强钩子、单场景/单冲突/反差反转，结局可开放、讽刺、反转或戛然而止，不强制完整故事闭环。
- 竖屏短剧：强冲突、集末留钩、打脸反转、爽文逻辑，允许善恶有报和主角圆满逆袭。
- 电影：完整叙事、人物弧光、氛围质感和主题表达优先，结局服务主题，可圆满、遗憾、开放或悲剧。
- 脱口秀：单人纯语言表达，无剧情线、无人物表演冲突、无故事闭环需求，用观点密度、吐槽节奏和结尾金句收束。

同时新增通用反偏置规则：除非用户明确指定竖屏短剧、爽文、甜宠圆满或大团圆，否则不得自动把故事收束为善恶有报、所有人和解、主角圆满胜利。

后续又补充了一条格式规则：即使是脱口秀，也必须遵守当前 Agent 要求的输出格式，不能因为“纯语言表达”而改成散文稿、台本段落或解释性文字。

## ConceptPitchAgent

**修改前：**

概念阶段主要负责生成 logline、核心冲突和情感基调，但没有明确要求先判断用户指定的视频风格。它容易把所有内容都往完整故事、高概念冲突和最终闭环方向推，即使用户要的是抖音短视频或脱口秀，也可能在概念层面埋下“大团圆”“完整人物弧光”的默认方向。

**修改后：**

在 `concept_pitch_agent.py` 中注入 `{video_style_guide}`，并增加风格判断和结局偏置约束：

- 先识别用户是否指定抖音短视频、竖屏短剧、电影或脱口秀。
- 概念阶段必须服从用户指定的视频风格。
- 不再默认把概念设计成善恶闭环、大团圆、全员和解。
- 抖音短视频概念可只围绕单一场景、单次冲突或反差瞬间展开。
- 脱口秀概念不再设计人物冲突线或剧情闭环，而是围绕观点、吐槽对象和情绪共鸣组织。
- 竖屏短剧仍保留强冲突、爽点、反转和圆满逆袭逻辑。
- 电影概念强调主题、人物复杂度和结局服务表达。

## CharacterVoiceAgent

**修改前：**

人物声音阶段主要检查人物设定、人设一致性、人物动机和角色语言，但没有区分不同内容形态对人物复杂度的需求。所有风格都可能被要求补充较完整的人物成长线、人物关系和行为逻辑。

**修改后：**

在 `character_voice_agent.py` 中注入 `{video_style_guide}`，并增加不同视频风格下的人物处理规则：

- 抖音短视频：人物可以轻量化、标签化、网感化，不强制补完整背景和成长弧。
- 竖屏短剧：人物要极致鲜明，正邪、欲望、爽点和身份反转要清楚。
- 电影：人物应更立体复杂，可以有矛盾、留白和非直白成长。
- 脱口秀：不按影视角色关系处理，重点检查单人表达者的语言风格、观点立场、吐槽节奏和个人口吻。

这样人物阶段不再把所有题材都统一拉成完整戏剧人物塑造，而是根据视频类型决定人物设计深度。

## NarrativeArchAgent

**修改前：**

叙事结构阶段主要检查故事节拍、幕次推进、因果关系和结尾闭环。默认会倾向于判断“完整结构”和“闭环结局”是否成立，容易把开放式、碎片化、讽刺式或脱口秀式收束误判为结构不完整。

**修改后：**

在 `narrative_arch_agent.py` 中注入 `{video_style_guide}`，并增加风格化结构判断：

- 抖音短视频允许弱化完整叙事，以快速钩子、单次反差或情绪瞬间成立。
- 竖屏短剧继续要求强冲突、连续反转、集末留钩和爽文闭环。
- 电影允许铺垫、留白、开放结局、遗憾结局或主题性悲剧。
- 脱口秀不再要求剧情线、人物冲突、故事闭环，只检查观点推进、段子递进和结尾金句是否成立。

新增约束：不得把所有风格强行修正成完整三幕剧或圆满结局；结构是否合格要先看用户指定的内容类型。

## TreatmentAgent

**修改前：**

分场大纲阶段负责把前置信息整理成 beat sheet，重点是每个节拍的 objective、conflict、outcome 和状态变化。原来它更偏传统戏剧节拍，容易在最后一个 beat 中补出圆满收束或明确善恶结果。

**修改后：**

在 `treatment_agent.py` 中注入 `{video_style_guide}`，并新增“风格化结尾设计”任务：

- 根据用户指定风格决定开放、讽刺、反转、留钩、圆满、遗憾或金句收束。
- 禁止未经用户指定就把结尾写成善恶有报、大团圆、全员和解。
- 逐行质检中新增“结尾风格匹配”检查项。
- `draft_guidance` 需要把风格要求传递给 DirectorAgent，避免导演起草阶段重新回到默认圆满逻辑。

对于脱口秀，TreatmentAgent 现在会把 beat 理解成观点和段子推进，而不是传统剧情推进。

## DirectorAgent

**修改前：**

导演起草阶段负责最终输出剧本 JSON，但原 prompt 更强调完整场景剧本、人物冲突、走位、动作和镜头字段。虽然能生成结构化 JSON，但在叙事倾向上容易自动补全故事闭环；脱口秀这种非剧情内容也容易让模型输出普通文本稿，而不是严格 JSON。

**修改后：**

在 `director_agent.py` 中注入 `{video_style_guide}`，并新增最高优先级的“视频风格与结局逻辑”规则：

- 如果用户明确指定抖音短视频、竖屏短剧、电影、脱口秀等风格，必须严格遵守视频风格指南。
- 除非用户明确指定竖屏短剧、爽文、甜宠圆满或大团圆，否则不得自动写善恶有报、所有人和解、主角圆满胜利。
- 抖音短视频可以开放、讽刺、反转、戛然而止。
- 电影结局服务主题，可圆满也可遗憾、开放、悲剧。
- 脱口秀不写剧情闭环，用观点和金句收束。

后续针对 eval 中暴露的问题，又补充了脱口秀 JSON 输出规则：

- 脱口秀也必须输出下方 JSON 数组结构，不能输出散文稿、逐字稿说明、Markdown 或非 JSON 文本。
- 脱口秀实现方式是把单人表演拆成多个 `shot="character"` 的对白/旁白片段。
- `speaker` 使用表演者真实角色名，`content` 写口语化段子。
- 可以没有 `move` 片段，但每个片段仍必须有 `current position`、镜头字段和动作字段。
- `scene information.what` 写“某角色围绕某主题进行单人脱口秀吐槽”，不要写角色冲突解决或剧情闭环。

这个修改修复了“单人脱口秀风格”测试中 DirectorAgent 不输出合法 JSON 的问题。

## CriticAgent

**修改前：**

审查阶段主要检查叙事逻辑、人物一致性、结构完整性和问题定位。因为默认审查标准偏完整剧情，它可能把开放式结尾、讽刺式收束、抖音短视频的碎片化表达，或脱口秀没有剧情闭环的状态判断为“不完整”。

**修改后：**

在 `critic_agent.py` 中注入 `{video_style_guide}`，并增加风格匹配审查逻辑：

- 审查前先判断用户指定的视频风格。
- 不把抖音短视频的开放、讽刺、反转、戛然而止误判为结尾缺失。
- 不把电影的遗憾、开放、悲剧、留白误判为需要大团圆修复。
- 不把脱口秀没有剧情线、人物冲突、故事闭环误判为结构错误。
- 只有竖屏短剧、爽文、甜宠等明确类型，才把爽点、反转、留钩、圆满逆袭作为主要审查标准。

这样 CriticAgent 的修订建议不会再把所有风格往同一种圆满闭环方向拉。

## DialogueAgent

**修改前：**

对白审查阶段主要检查角色台词是否自然、有个人语言特征、是否有 AI 腔、是否符合人物设定。它没有明确区分不同视频形态下的语言节奏，所以抖音、电影、脱口秀、竖屏短剧可能被同一套对白标准审查。

**修改后：**

在 `dialogue_agent.py` 中注入 `{video_style_guide}`，并增加不同风格的语言检查规则：

- 抖音短视频：语言可以更轻、更快、更网感，允许口语梗、短句和快速反差。
- 竖屏短剧：语言可以更外放，情绪爆点、打脸、撒糖、反转语气要更直接。
- 电影：语言更克制，允许潜台词、沉默、留白和非直白表达。
- 脱口秀：重点检查观点密度、段子节奏、吐槽力度、个人口吻和结尾金句，不按人物对白冲突标准强行审查。

这样 DialogueAgent 能更准确地判断“这句话是否适合当前视频类型”，而不是只判断它是否像传统剧本对白。

## 未改动的 Agent / 阶段

**修改前：**

摄影、镜头、站位、技术校验、标题生成等阶段不直接决定故事风格和结局倾向，主要负责镜头规划、坐标计算、结构校验或标题生成。

**修改后：**

本次没有把视频风格指南注入以下阶段：

- ShotPlanning 相关 prompt
- CameraPlanning 相关 prompt
- PositionAgent 相关 prompt
- ValidationAgent
- TitleGenerationAgent
- DirectorAgent_Direct

原因是这些阶段不是造成“大团圆结尾”的主要来源。直接生成模式 `DirectorAgent_Direct` 的职责是结构化用户已有剧本并尽量保留原文，也没有参与本次风格创作逻辑改造。
