# Prompt 风格化改造明细

## ConceptPitchAgent

**修改前：**

- 主要负责提出故事概念、核心冲突、卖点和基础创作方向。
- 没有统一的视频风格判断规则。
- 当用户输入“抖音短视频”“电影”“脱口秀”等风格时，prompt 没有明确要求概念阶段区分不同内容形态。
- 没有明确禁止“未经用户指定就默认大团圆、善恶闭环、所有角色和解”。

**修改后：**

- 注入 `{video_style_guide}`，共享四类视频风格说明：抖音短视频、竖屏短剧、电影、脱口秀。
- 新增要求：若用户明确指定视频风格，故事概念必须服从该风格的节奏、结局逻辑和情绪出口。
- 新增红线：不得未经用户指定就默认大团圆、善恶闭环、所有角色和解。
- 让概念阶段先决定“这是什么类型的视频”，再决定故事卖点，避免所有题材都被引导到统一圆满结局。

## CharacterVoiceAgent

**修改前：**

- 主要负责检查和定义角色声音、语言习惯、表达方式。
- 角色复杂度判断没有和视频风格绑定。
- 默认更偏向常规影视角色塑造，容易要求所有内容都具备较完整的人物铺垫和人物弧光。

**修改后：**

- 注入 `{video_style_guide}`。
- 新增要求：按用户指定风格判断人物复杂度。
- 抖音短视频允许角色更符号化、瞬时化，服务单次冲突或反差。
- 竖屏短剧允许人物标签更极致、正邪对立更鲜明。
- 电影要求人物更立体复杂，服务人物弧光和主题表达。
- 脱口秀以表达者视角、语言人格和观点密度为核心，不强行设计多人物戏剧冲突。

## NarrativeArchAgent

**修改前：**

- 主要负责判断叙事结构、节奏、冲突推进和结局完整性。
- “结构合理”容易被理解为完整起承转合和闭环收束。
- 对抖音短视频、脱口秀这类非完整剧情形态缺少豁免规则。
- 没有明确禁止把所有风格都改成完整大团圆闭环。

**修改后：**

- 注入 `{video_style_guide}`。
- 新增要求：按用户指定风格判断“结构合理”。
- 抖音短视频不需要完整故事闭环，可以开放、讽刺、反转或戛然而止。
- 竖屏短剧需要强冲突、集末留钩和爽感闭环。
- 电影结局服务主题，可以圆满、开放、遗憾或悲剧。
- 脱口秀不需要剧情线和人物冲突闭环。
- 新增红线：不得把所有风格都强行改成完整大团圆闭环。

## TreatmentAgent

**修改前：**

- 主要负责根据创意会议内容生成分场大纲和 draft guidance。
- 结尾设计没有独立的风格化判断。
- 容易把分场推进自然导向善恶有报、全员和解、主角圆满胜利。

**修改后：**

- 注入 `{video_style_guide}`。
- 新增任务：风格化结尾设计。
- 要求根据用户指定风格决定结尾是开放、讽刺、反转、留钩、圆满、遗憾还是金句收束。
- 新增红线：未经用户指定，不得把结尾写成善恶有报、大团圆、全员和解。
- 新增检查点：结尾必须匹配用户指定的视频风格，不默认圆满。

## DirectorAgent

**修改前：**

- 主要负责生成最终剧本 JSON。
- 核心规则集中在幕数、角色数量、走位设计、动作决策、对白口语化、感官细节、角色声音区分、镜头字段结构等。
- 没有最高优先级的视频风格判断规则。
- 对结局没有明确约束，容易在最终起草阶段把故事写成善恶有报、所有人和解、主角圆满胜利。

**修改后：**

- 注入 `{video_style_guide}`。
- 新增最高优先级章节：`视频风格与结局逻辑`。
- 明确要求：如果用户指定抖音短视频、竖屏短剧、电影、脱口秀等风格，必须严格遵守视频风格指南。
- 明确禁止：除非用户明确指定竖屏短剧、爽文、甜宠圆满或大团圆，否则不得自动写善恶有报、所有人和解、主角圆满胜利。
- 明确允许：
  - 抖音短视频可以开放、讽刺、反转、戛然而止。
  - 电影结局服务主题，可以圆满，也可以遗憾、开放、悲剧。
  - 脱口秀不写剧情闭环，用观点和金句收束。
- 这是防止“无论生成什么都包饺子”的最核心修改点。

## CriticAgent

**修改前：**

- 主要负责审查剧情逻辑、角色一致性、结构问题和具体字段问题。
- 容易把开放式、讽刺式、遗憾式、碎片式结尾判断为“叙事不完整”。
- 审查标准没有明确区分不同视频风格。

**修改后：**

- 注入 `{video_style_guide}`。
- 新增审查维度：风格适配评估。
- 要求根据用户指定视频风格判断结局是否合理。
- 不得把开放式、讽刺式、遗憾式、碎片式或脱口秀金句收束误判为不完整。
- 新增红线：不得把所有非圆满结局都判为叙事问题。
- 新增检查点：只在结局违背用户指定风格时提出问题。

## DialogueAgent

**修改前：**

- 主要负责检查对白质量、角色语言一致性、口语化程度和 AI 腔问题。
- 审查标准更偏现实主义影视对白。
- 容易把网感表达、强情绪短剧台词、脱口秀观点密集输出误判为“不够克制”或“不够自然”。

**修改后：**

- 注入 `{video_style_guide}`。
- 新增审查维度：风格语言校验。
- 抖音短视频允许网感、碎片化、快速情绪表达。
- 竖屏短剧允许情绪外放、直白冲突、爽点式语言。
- 电影偏克制、留白、人物潜台词。
- 脱口秀强调观点密度、个人口吻、吐槽节奏和段子感。
- 新增红线：不得用电影对白标准否定脱口秀、抖音短视频或竖屏短剧的风格化语言。

## VideoStyleGuide

**修改前：**

- 不存在统一的视频风格指南 prompt。
- 各 agent 没有共享同一套风格分类、结局逻辑和审查标准。
- 风格识别依赖模型自行理解，容易出现不同 agent 标准不一致。

**修改后：**

- 新增 `video_style_guide.py`。
- 文件中只放一个纯文本 prompt 变量：`video_style_guide_prompt = """..."""`。
- 统一定义四类风格：
  - 抖音短视频：极速节奏、强钩子、弱完整叙事、结局灵活。
  - 竖屏短剧：强冲突、集末留钩、爽文闭环、大团圆为主。
  - 电影：完整结构、人物弧光、主题表达，结局服务主题。
  - 脱口秀：单人语言表达，无剧情闭环，观点和金句收束。
- 统一反默认规则：除非用户明确指定竖屏短剧、爽文、甜宠圆满、大团圆，否则不得自动把故事收束为善恶有报、所有人和解、主角圆满胜利。

## PromptRenderer

**修改前：**

- 各 agent system message 只渲染自身 prompt 和原有上下文。
- 没有向创作链路统一传入视频风格指南。

**修改后：**

- 在 `autogen_agent_prompts.py` 中引入 `video_style_guide_prompt`。
- 将 `video_style_guide=video_style_guide_prompt` 注入以下 system message 构建函数：
  - `build_director_system_message`
  - `build_treatment_system_message`
  - `build_critic_system_message`
  - `build_dialogue_system_message`
  - `build_concept_pitch_system_message`
  - `build_character_voice_system_message`
  - `build_narrative_arch_system_message`
- 保证概念、人物、结构、分场、起草、文学审查、对白审查使用同一套风格判断规则。

## 未修改的 Agent

**修改前：**

- 摄影、站位、技术校验、标题等 agent 不直接负责故事风格和结局走向。

**修改后：**

- 暂未注入 `video_style_guide`。
- 原因是这些 agent 主要处理镜头规划、角色坐标、动作/JSON 校验、标题生成等技术或后处理任务。
- 当前问题的根因集中在创作链路和审查链路，因此本次只修改 7 个相关 agent 和共享风格指南。
