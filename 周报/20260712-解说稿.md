# 20260712 周报解说稿

这周主要完成了 ScriptAgent 从本地环境搭建到公网访问链路打通的工作。

一开始拿到的是一份重新 clone 的项目，所以先从运行环境开始配置。项目要求使用 Python 3.12，但机器默认版本是 Python 3.11，因此没有改动系统 Python，而是使用 `uv` 在项目根目录单独创建了 Python 3.12 虚拟环境，再安装 `backend/requirements.txt` 中的依赖，并根据示例生成本地 `.env` 配置。环境完成后，对后端核心 Python 文件进行了编译检查，对前端 JavaScript 文件进行了语法检查，最后临时启动服务并访问 `/api/health`，确认环境不是只完成了依赖安装，而是能够真正运行。

接着处理 `5001` 端口的服务接管。机器上原来残留了多份 `backend/app.py` 相关进程，同时 Flask 的 debug 重载机制还会派生子进程，因此端口上曾出现多个 Python 监听实例。处理时先清理旧进程，再使用项目原生方式重新启动后端，最后核对监听进程并访问健康检查接口，确认 `5001` 已经由当前 ScriptAgent 服务稳定接管。

服务启动后，公网地址 `https://couvzob.kdns.fr/script/` 仍然返回 `Not Found`。排查后确认问题不在 Cloudflare Tunnel 是否连通，也不在 `5001` 是否启动，而在路径和服务职责没有对齐。当时 Tunnel 已经把 `/script/*` 转发到 `127.0.0.1:5001`，但 Flask 只处理 `/api/*`，既不认识 `/script/` 前缀，也不负责返回前端页面，所以请求虽然成功到达后端，最终仍然会得到 404。

针对这个问题，后端增加了 `/script` 路径前缀的兼容和前端静态文件托管：外部的 `/script/api/*` 会映射到内部已有的 `/api/*`，而 `/script/`、`/script/js/*`、`/script/css/*` 等请求会从前端目录返回对应页面和静态资源。前端配置也同步调整，当页面运行在 `/script/` 下时，会自动使用 `/script` 作为 API 基址。这样浏览器访问页面和调用接口都走同一个公网域名、同一个路径前缀和同一个本地 `5001` 服务，现有 Tunnel 规则不需要改到 `8080`。

修复完成后，在本地分别验证了 `/api/health`、`/script/` 和 `/script/api/health`。其中 `/script/` 返回页面，`/script/api/health` 返回正常 JSON，公网地址随后也恢复正常访问。

最后补充了项目文档。`README.md` 现在区分了两种运行方式：本地开发仍然可以使用前端 `8080`、后端 `5001` 的分离模式；公网或 Tunnel 部署则可以把 `/script/*` 统一转发到 `5001`，由 Flask 同时提供前端和 API。`PROJECT_OVERVIEW.md` 也同步更新了架构描述，避免后续继续按照“后端只提供 `/api/*`”的旧认知部署。

代码最初提交在 `codex/script-path-support` 分支。后来拉取远端 `main` 并重启时发现，远端版本尚未包含这次修复，因此 `/script/` 再次返回 404。确认分支关系后，将修复分支快进合并到本地 `main`，过程没有冲突。当前本地 `main` 位于提交 `9e0626d`，重启后 `/api/health` 正常，`/script/` 返回 `200`。目前剩余事项是按需要将本地 `main` 的这次更新推送到远端。
