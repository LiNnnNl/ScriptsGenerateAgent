## 1. 剧本 JSON 最终格式合同落地

本次以飞书文档正文和已确认的规则为最高依据，新增共享剧本合同模块 `backend/src/script_contract.py`，把最终剧本从“依赖提示词约束”改成“代码强制校验”。

原来的逻辑主要依赖不同 Agent 的提示词和分散的旧校验；现在统一检查：

1）每幕必须包含 `scene information`、`initial position`、`scene`，并检查 `who / where / what / emotionLibrary / language_config`。

2）每个事件必须有 `event_index`、`current position`、`emotion`、`confidence`、`reason`、`shot_description`。

3）`initial position[].state` 和 `actions[].state` 固定为 `standing / sitting / kneeling / squatting`；动作状态表示动作执行前姿态，动作执行后会更新后续事件的姿态状态。

4）检查角色覆盖、Position 唯一占用、移动前必须站立、移动目的地连续性、动作兼容姿态、语言轨道、情绪权重、交互参数和镜头/位置文件的跨文件引用。

## 2. Agent 提示词和资源选择规则统一

新增 `backend/src/prompt_files/script_contract_rules.py`，并注入 Director、Direct Director、Word Director、Critic、Dialogue 以及摄影相关提示词。

现在提示词统一说明：

1）动作必须从 `actions_resource.json` 选择，并符合 `compatible_states`。

2）纯移动事件只能使用 `move`；边走边说在顶层使用 `speaker + content + move`；无说话人事件保留 `speaker=""`、原始 `content` 或“无台词”、数字秒数和 `actions=[]`。

3）默认语言为普通话；多语言必须通过 `language_config.tracks` 和 `content_variants` 表达，直接模式不擅自新增翻译。

4）交互对象只能从当前场景交互库选择；没有真实资源库时不自动生成交互，直接输入的交互结构保留但目标和动作清空并告警。

5）摄影资源使用场景锚点、LayoutLib 和 CameraLib；Position 是逻辑槽，不是带坐标的物品锚点。

## 4. 校验、暂存发布和前端下载保护

流程增加了发布门禁：

1）生成文件先写入 `outputs/.pending/<run>`。

## 5. 普通模式验收中的问题

普通模式已经完成模型生成、文学审查和摄影阶段，但在格式修复阶段触发了保护门禁：

1）第一次校验发现指定角色引用不完整，系统返回真实候选角色名。

2）模型修复结果改变了事件数量、顺序或对白文本。

- 对象 `id`
- 支持的动作 `name`
